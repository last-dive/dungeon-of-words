# NPC 设计文档

## 核心设计理念

本游戏的 NPC 设计遵循以下原则：

## 1. 人格定义

每个 NPC 都有明确的 system prompt，包含：

### 示例：法师 Merlin

```
你是 Merlin，一位古老而智慧的魔法师，甘愿成为勇者的向导。
你的性格：
- 忠诚友善，总是支持勇者
- 知识渊博，了解这片大陆的古老传说
- 偶尔会开些小玩笑缓解紧张气氛
- 关心勇者，会在战斗中提供战术建议
- 使用古典优雅的说话方式

你的能力：
- 可以使用治疗魔法恢复勇者 HP
- 可以使用攻击魔法对敌人造成伤害
- 可以感知附近的危险
- 知道一些关于 Boss 和公主的传说

在战斗中，你会根据情况给出建议。
```

## 2. 游戏目标关联

NPC 的行为与游戏目标紧密关联：

### Boss 行为逻辑

1. **战斗时**：会反击玩家，造成伤害
2. **被打败时**：会透露公主的位置 ("公主在...北塔...")
3. **对话时**：傲慢自大，但可能无意透露信息

### 公主行为逻辑

1. **未找到时**：位置保密
2. **Boss 死后**：位置对玩家可见
3. **玩家到达时**：触发胜利

## 3. 记忆系统

游戏中实现了两层记忆：

### 短期记忆 (游戏状态)

- 当前 HP/MP
- Boss 生死状态
- 公主是否被发现

### 长期记忆 (LLM 上下文)

- NPC 的人设 (system prompt)
- 游戏中发生的关键事件

## 4. 对话生成

当玩家与 NPC 对话时：

```
1. 收集当前游戏状态
2. 确定附近有哪些 NPC
3. 构建 prompt (人设 + 游戏状态 + 玩家输入)
4. 调用 LLM API
5. 返回生成的对话
```

## 5. 改进方向

### 当前局限

1. **Token 消耗**: 每次对话调用 API
2. **延迟**: 依赖网络和 API 响应速度
3. **一致性**: LLM 可能偶尔跳出人设

### 未来改进

1. **本地模型**: 使用本地 LLM 减少延迟和成本
2. **预定义回复**: 对常见场景预定义回复
3. **人格强化**: 使用更多约束确保一致性
4. **多轮记忆**: 实现跨会话的记忆系统
